## 三、主持人已裁定的口径（写进文档，不再重开）

### C1 仓库形态 = **单仓库 + npm workspaces**
证据：本机 `pnpm -v` 不存在、`npm 10.9.4` 可用；`core` 被 12 个包共享；单插件 `node_modules` 实测 69 MB，13 份独立安装 ≈ 900 MB，而本机 C 盘仅余 32.5 GB / D 盘余 229.7 GB（用户对磁盘占用敏感）。
备选：13 独立仓库贴样板（不推荐，零基础设施下无法共享 core）。

### C2 目录与装配分离 = **13 个源码目录，装配单元收敛为 3 个 patch + 1 个 client**
理由：单个变更横跨 5–6 个包（arch 席实测三条真实数据流：写 7 包 / 召回 5 包 / 巩固 4 包），13 行 patch 会把耦合成倍放大到装配面。目录保留便于分工，装配面收敛便于回滚。

### C3 测试/CI 工具链 = **node:test**
证据：本机**无 vitest**（`node_modules\vitest` 不存在、样板 package.json 未提及）；样板 `test` 脚本实为 `node --test "test/*.test.mjs"`，32 个测试文件、实测 365/365 通过、2.59 s。
**写法硬规定**：`node --test "tests/*.test.mjs"`（glob）或 `node --test`（无参自动发现）。
⚠ **禁止写成 `node --test tests/`**——实测该写法在本机失败并打印 `# tests 1 / # fail 1`，**形似「测试失败」实为「命令写错」**，会把执行者误导去查测试代码。

### C4 检索路线 = **先用物化 BLOB + 纯 JS 余弦，vec0 列为规模化升级项**
证据（两条实测相冲，以数字为准）：
- 暴力 JS 余弦 10k 条 = **20.92 ms**；sqlite-vec vec0 KNN 10k 条 = **35.877 ms** ⇒ 当前量级下暴力法**既更简单又更快**。
- 但 sqlite-vec 在本机**确实可用**（主持人真机实证：`npm pack sqlite-vec-windows-x64@0.1.9` 取到 `vec0.dll` 289,280 B，`new DatabaseSync(':memory:',{allowExtension:true})` + `loadExtension` 成功，`vec_version()=v0.1.9`，KNN 返回 `[{"rowid":1,"distance":0},{"rowid":2,"distance":1.0954450368881226}]`）。
⇒ 决策：阶段 2 走纯 JS 余弦（复用 shoucang `lib/vec.js` 的 `cosine` + RRF k=60）；**但阶段 0 建库一律 `{allowExtension:true}`**（零成本预留升级窗口），vec0 在数据量 > 10 万条时启用。

### C5 多设备同步 = **移出范围**
证据：方案全文仅行 1140 五个字、零设计；与行 785「本地 SQLite 单文件」+ 行 911「本地优先/隐私」张力。记为独立课题，重启判据＝出现明确的跨设备冲突解决设计。

### C6 I1/I2 计数维度 = **阶段 0 补 `session_id` + `turn_id` 列**
证据：方案 §6.1 行 442–443 要求按 `(session,turn)` 计数，但 §11.2 行 790–863 的 6 张表**无此列**，`mana_trace` 仅 `(seq,event_type,payload,timestamp)` ⇒ 不变式当前**无可数之处**。不补列，I1/I2 判据永久不可验。

### C7 方案 §13.2 的 7 个目标值 = **全部改标「待定，需首测后自设」**
证据：记忆命中率>85%、R²>0.8、延迟<500ms、完成率>80%、降级率<5%、缓存>40%、用户精度>75% —— 本机**一个都没有实测基线**。先定标准后补数据正是本册要避免的。
延迟特别处理：实测热态三件套和 = **55.46 ms**（单条嵌入热 p95 19.2 ms + vec0 KNN 35.877 ms + FTS5 0.387 ms），固定 500 ms 会把能力缺陷掩盖在里面 ⇒ 放行线用「阶段 2 首日实测 p95 × 1.2」自基线。

### C8 JEV 承载 = **阶段 1 用本机 Ollama logprob 合成 noul + mock 验降级链**
证据：LitJev 需 H100/27B，本机（RTX 2070S 8 GB）不可行；Ollama logprob 可合成 noul（实测 `yes=0.887 / no=0.101`），但 50 并发单次 **5785 ms** ⇒ 并发是硬约束，须在阶段 1 就定串行/批处理策略。

### C9 §14「检测方式」列 = **入阶段 0 硬判据**
证据：scenario 席判定 §14 十条检测方式中 **真有信号 0 条 / 半真 3 条 / 愿望 7 条**。本项目**只有一名使用者、无「用户报障」通道** ⇒ 测不出来的失败就是永久静默失效。每条故障模式必须给出表/字段名落点，给不出即标「不可观测」并入缺口清单。

### C10 工期 = **双口径并列**
人类等价工期保留方案 §17 原值（实算 **20–30 周**，非方案所写 34）；agent 口径用「**17 批次，其中关键路径 11 批次**」，不估小时数（无依据）。

### C11 契约冻结 = **灰度分版**，不一次性全冻
v0.1（阶段 1 所需五类事件）→ v0.2（长时记忆增补）→ v0.3（巩固遗忘增补）。依据 §10.4 行 774「services 之间靠事件通信、不直接 import 实现」，事件声明合并使新增事件不破坏既有订阅者。这是**唯一的总工期压缩杠杆**：契约 v0.1 冻结后最大并行扇出 **7 路**。

### C12 阶段 0 只建 P0 六个骨架（core/jev/vector/perception/attention/working-memory）
P1 四个在 B2.2 建、P2 三个在 B5.1 建。理由：13 个空壳同批装配后，面板上分不出哪几个真有行为，后续每批失败被 13 项等权清单稀释。
