## 一、六条

### 1. 判据器带锁：同一 checker 单实例

同一 checker 同时只允许一个实例在跑。锁内容 = **pid + 起始时刻 + commit**；
第二个实例必须**非零退出并打印持有者信息**（pid / 起始时刻 / commit）。

**禁静默排队**（排队 = 失败不可观测）。

> **为什么**：会议期间 `ps` **实拍到三方并发跑同一检查器**（`docs/mana-v10-review-and-allocation.md:82`）。
> 判据器读的是**共享可变工作树**：并发实例会互相把对方的在途码读进自己的读数里，
> 于是「谁把这条判据搞红的」在结构上不可归因。而「排队等待」并不解决问题 ——
> 它把「两个实例同时在跑」这件事实**变成不可见**，只留下一个看似正常的等待，
> 正是本项目最在意的那类缺陷形态（**让失败不可观测**）。

### 2. `--record-baseline` 唯一基线席，且前置 `git status --porcelain` 为空

`node tools/a0-check.mjs --record-baseline` **只能由唯一基线席**执行；
执行前必须满足 **`git status --porcelain` 为空**（工作树干净）。其他席**不得**执行该开关。

> **为什么**：本轮实测 —— `docs/contract/_freeze.head` 在**脏树**上被写，随后被回滚
> （07:30:31 写 → 07:53:27 回滚；v10 评审 §D7）。基线记录动作会把「写入时刻的仓态」
> 钉成后续判据的比较基；在脏树上记录 = 把**别席的在途状态**当成「只有本席的已知态」，
> 之后所有基于该基线的判据都在一个**归属不明**的基上判绿。
> （该前置门现已由 `tools/a0-check.mjs` 的 `--record-baseline` 分支**强制**：脏树即拒绝记录。）

### 3. 取数三元组：缺一项即标「浮动读数」，不得进结论

任何读数进结论前必须带齐四项：

| # | 项 | 取值方式 |
|---|---|---|
| 1 | **commit** | `git rev-parse --short HEAD` |
| 2 | **checker-md5** | `md5sum tools/*-check.mjs` |
| 3 | **env 关键变量** | 至少含 `node -v`、`NODE_USE_ENV_PROXY` 等门控项 |
| 4 | **时刻** | 本地时刻（带时区）|

缺任一项 ⇒ 该读数标 **「浮动读数」**，**不得进结论**（只可作测量条件说明）。

> **为什么**：会议期间 **HEAD 移动 3 次**、`tools/a1-check.mjs` 项数 **15 → 16**，
> 且该变化**不是机器报警发现的，是人工比对发现的**。同一工作树 30 分钟内 A0 全量可翻转 ⇒
> 没有 commit + checker 指纹的读数**无法复现也无法归因**。分档规则见 `threshold-discipline.md`（B 档只进测量条件说明）。

### 4. git 单写者 + 禁 `git add -A` / `git add .`

同一波次**只有一个 git 写席**。其余席只写自己的工作树文件，**不提交**。
任何席**禁止** `git add -A` / `git add .`；只能逐条 `git add` **自己写面内**的文件（+ 自己的交接单）。

> **为什么**：并行波次里工作树上同时有 4–6 席的在途改动。`git add -A` 会把**别席未完成的、
> 可能编不过的、可能带调试残留的**改动卷进你的提交 —— 提交信息与实际内容失配，
> 且事后无法从提交历史分辨「哪部分是谁的」。开工记 `git log --oneline -1` 与
> `git status --porcelain`，收工**再记一次**，读数必须带时刻。

### 5. 禁并发 build 同一 workspace

禁止在并行波次里跑 workspace 级构建（`npm run build` / `npm test` 之外的产物生成）；
要验只 **build 自己那个包**。

> **为什么**：`packages/*/lib/` 是**共享产物目录**（`packages/core/package.json:8` main → `./lib/index.js`）。
> workspace 级构建会**把别席的在途源码编进你的 lib** ⇒ 后续所有「解析型腿」（按包名 → lib）
> 的判据都在读一份**归属不明的产物**。v10 评审 §D5 已实测 lib/src 双向漂移
> （core: src 新于 lib；vector: lib 新于 src），产物层的归属错乱**会直接改变判据的绿**。

### 6. 改 `tools/*-check.mjs` 须在提交信息写明期望项数变化

修改任一 checker 的提交，提交信息**必须**写明期望项数变化，例：`15 → 16`；无变化写 `16 → 16`。

> **为什么**：本轮判据项数 **15 → 16** 无人声明，是**人工比对**发现的，不是机器报警 ——
> 若当时无人比对，「判据集合悄悄变了」会与「判据全绿」同时成立，
> 这正是「**判据绿 ≠ 事实被检查**」的入口形态。
> 项数是判据集合的**可数指纹**：把它写进提交信息，下游才有一个可比对的确定值。

## 二、变更流水（`docs/contract/_freeze.log`）

第 2 条只约束「谁在什么条件下记录」，**不解决「记录过又被改回去」不可见**（v10 评审 §D7）：

- 实测循环：`_freeze.head` **07:30:31 被 `--record-baseline` 写入**（当时 HEAD `76fcce7`）→ **07:53:27 被回滚**回 `ee9e22e`；
- 回滚后三种常规检查**全部看不出**：文件值 = 初始值、`git status docs/contract/` 为空、三件套内容与 HEAD 版一致；
- 而 A0-12 的 HEAD 腿判据是「快照锚点仍是祖先（`ee9e22e ⊑ 现 HEAD`）」⇒ **回滚后照样通过**
  ⇒ 一个**什么都没做**的动作被判通过。

**处置**：契约快照在「三件套」之外增列**append-only 变更流水** `docs/contract/_freeze.log`（JSON Lines，一行一条）：

| 字段 | 含义 |
|---|---|
| `seq` | 单调序号（追加序，不重排）|
| `at` | 记录时刻（带时区）|
| `kind` | `init`（引入机制时的初始记录）/ `record`（基线重取）/ `incident`（事后追溯的事故记录）|
| `actor` | 记录者（席名 / 工具名）|
| `note` | 人可读说明；`incident` 必须写明**来源**（不是本次实测的，不得写成本次实测）|
| `head` / `headShort` | 记录时的仓 HEAD |
| `files` | 三件套**磁盘字节**的 `sha256` + `bytes` + `mtimeMs`（读取自磁盘，非内存值）|

A0-12 据此判**两条新增腿**：

- **流水腿**：流水末条的 `files` 哈希必须与**当前磁盘**三件套逐字相等
  ⇒ 任何「记录之后又被改写」的状态都报红（含**写了又回滚**：回滚后的磁盘 ≠ 曾记录的状态）。
- **锚点不回退腿**：流水内 `head` 锚点只能**向前**（前一条必须是后一条的祖先）
  ⇒ 「回滚到旧锚点后重新记录」这种把不可见状态洗白的手法仍留痕。

⚠ **未覆盖面（如实标注）**：完全**绕开记录路径**的「手工写 → 手工回滚」不会进入流水，
其原因与 A0-12 只把 mtime 作**提示性证据**而不判红相同 ——
**mtime 可被 `touch` 伪造，且 `git clone`/checkout 会把它整体重置**，
若据此判红会造出「一会儿过一会儿不过」的判据（`threshold-discipline.md` 明令禁止）。
该项列为**未覆盖面**，需更上层取证（git 对象层 / 审计）才能闭合。
