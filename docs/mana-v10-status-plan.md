# 第三部分：理论基础

## 4. ACT-R 认知架构

### 4.1 记忆激活方程

```
A_i = B_i + S_i + P_i + ε
```

- **A_i**：总激活值
- **B_i**：基础激活值
- **S_i**：关联激活
- **P_i**：部分匹配惩罚
- **ε**：噪声项

✅ **本仓逐字实现**（`packages/long-term/src/activation.ts:100`）：

```typescript
return b + (opts.associative ?? 0) + (opts.partialMatch ?? 0) + (opts.noise ?? 0)
```

⚠ 随机性**只在 `noiseTerm(rng)` 里显式传入 rng**（默认 `Math.random`，测试传固定序列）——读时钟/读随机数会让判据「一会儿过一会儿不过」，是阈值纪律明令禁止的形态。

### 4.2 基础激活（幂律衰减）

```
B_i = ln( Σ_j (t_j)^(-d) )
```

✅ **本仓真实现**（`activation.ts#baseLevel`，A2-1 锚点 `B{[1]}`）。⚠ **单位是秒**（"1 秒前访问过一次"），与 §4.4 的半衰期（**天**）**不是同一个量**，两者**不得相乘**（C14「派生量唯一写者」）。

### 4.3 检索概率与延迟

```
检索概率：Prob_i = 1 / (1 + e^(-(A_i - τ) / s))
检索延迟：Time_i = F · e^(-f · A_i)
```

✅ **两条都真实现**（`activation.ts:110` `retrievalProbability`、`:129` `latencyMs`）：

- `retrievalProbability(a, tau=TAU, s=S_NOISE)` —— **`s` 是派生量** `s = √3σ/π`，不是配置项；
- `latencyMs(a, tau=TAU)` —— 含 **τ 下界**（`effective = a >= tau ? a : tau`），A2-2 锚点 `s(σ=0.3)=0.165399` 已复现。

## 6. JEV 决策模型

### 6.1 三种原语

| 原语 | 回答的问题 | 返回内容 | 本仓实测 |
|---|---|---|---|
| **Choice** | 从给定选项中选一个 | 选中选项 + 概率 + 置信度 | ✅ 真通道已亲探（`criteria` 是**对象**，键=返回值） |
| **Noul** | 某个陈述成立的概率 | 是/否的概率（0–1） | ✅ 缺省通道（ollama logprobs pos0 归 yes/no 族求和） |
| **Score** | 在有序量表上的位置 | 加权位置 + 每级概率 | ✅ ⚠ `criteria` 必须是**数组**（对象会 400） |

### 6.2 核心特性

- **不生成文本**：仅返回类型化决策 ✅ **架构性保证**（`noul` ⇒ 单值概率；`choice`/`score` ⇒ `value:'unknown'` + `probability:null`，**不得用 0 冒充**）
- **并行输出**：50 个问题和 1 个问题耗时相近 —— ⚠ **实测不成立**，见 §24.1
- **性能**：延迟 70–500ms；输入 $0.042/1M token，输出免费 —— ⚠ 本仓**无该采样**；`cost_usd` 列在（`schema.ts:166`），实测 ~1.2e-5 USD/次（**B 档浮动量，不得当阈值判据**）
- **模型 ID**：`typesafe/jev-1.13` —— ⚠ 本仓不是独立通道，仅以**模型别名**出现在服务端白名单
- **上下文**：32,000 tokens —— 服务端事实，本仓无落点

# 第六部分：ITACL 轮次内主动消费循环

## 19. ITACL 核心设计

> ⛔ **实况总述：本仓不移植 ITACL（§19–§21 全节）。**
> **理由（可复跑）**：宿主 `agent/pre-step` 的返回类型只有两种（`@deepseek-ai/dsh-agent/lib/types/runtime-types.d.ts:92-99`）：
> ```typescript
> export type PreStepDecision =
>   | { kind: 'reject' }
>   | { kind: 'enter'; messages: UserMessage[]; startsRequestSeries?: true }
> ```
> **没有「信息充足度」通道** ⇒ §19.4 状态转移表与 §20.4 的 0.7/0.6 阈值**无处落**。照写即两个**假旋钮**。
> **本节以下各小节骨架保留（便于对照），内容改写为「v10 设想 vs 宿主契约」的裁定说明。**

### 19.1 定义

**ITACL（Intra-Turn Active Consumption Loop）**：在单次对话轮次内，持续执行「观察 → 判断 → 检索 → 行动 → 反馈」循环，直到信息充足且任务完成。

⚠ **本仓裁定**：该「直到信息充足」的**终止判据在宿主侧不存在**。宿主 pre-step 只回答「进/拒」，不回答「够不够」。

### 19.2 三阶段

```
┌─────────────────────────────────────────────────────────────────────────────┐
│              ITACL：轮次内主动消费决策循环（⛔ 本仓不移植）                  │
│                                                                             │
│   ┌─────────────────────────────────────────────────────────────────────┐   │
│   │ 阶段一：任务前信息采集（Pre-Task Information Gathering）           │   │
│   │  意图识别 → 任务复杂度评估 → 信息需求分析                          │   │
│   │  → 多源预检索（本地记忆 + 网络 + 工具）                            │   │

### 20.1 阶段一：任务前信息采集

```text

  → ① 意图识别（LLM）：问答/任务/提醒/闲聊

### 20.2 阶段二：执行中观察-反馈循环

```text

  → ① 执行一步行动
  → ② 观察结果
  → ③ 结果分类（JEV Choice）：success/failure/anomaly/uncertain/partial

```
⚠ ③④ 需要「执行一步」这个动作的归属者 —— 宿主 agent loop 才是执行者，插件无法代它循环。

### 20.3 阶段三：任务完成与固化

```text
任务完成
  → ① 结果验证（JEV Noul）
  → ② 新知识提取（LLM）
  → ③ 记忆写入（编码链条）
  → ④ 再巩固触发
  → ⑤ 学习触发

```
⚠ ③④⑤ 的**被调方**已存在（`long-term` / `reconsolidation` / `learning`），但**无触发者**（无「任务完成」事件源）。

### 24.1 并行问题评估

⛔ **本仓实测该前提不成立**（`qwen3.5:0.8b`、`think:false`、`temperature:0`）：

|---|---|

⚠ **准入顺序本身就是语义**（判据逐条钉住）：**预算 → 缓存 → 熔断 → 半开探针 → 并发槽 → 模型**。
缓存命中**不受熔断阻断**（代价 0 次 fetch，服务于「熔断开时仍可给上一次的好答案」）。
缓存命中 / 熔断拒绝 / 超预算 / 并发超时 / 模型降级**五条非正常路径都会落一行 `jev_log`**，
由 `makeJevOutcome()` **唯一出口**结构性保证 —— **不存在「什么都没发生」的静默分支**。

**六项护栏配置（全部真被 `apply()` 消费）**：

| 配置键 | 缺省值 | 语义 |
|---|---|---|
| `cacheTtlSeconds` | 300 | 判定缓存 TTL（键 = `state_hash` + 分隔符 + question） |
| `circuitBreakerFailures` | 5 | 连续失败达此值 ⇒ 熔断打开 |
| `circuitBreakerCooldownSeconds` | 60 | 冷却到点后进入 half-open，且**只放行一个试探** |

```typescript
export const name = 'mana-jev'
/** 依赖 core（方案 §9.1）。缺 core 时本插件停在 waiting，不半启动。 */
export const inject: string[] = ['mana-core']

export function apply(ctx: Context, config: Config): void {
  const core = ctx.get('mana-core')
  if (!core) throw new Error('mana-jev: 缺少 mana-core 服务（inject 未满足，不应半启动）')

  const guard = new JevGuard({ cacheTtlSeconds: config.cacheTtlSeconds, /* … 五项 */ })
  guard.setWaitTimeoutMs(config.concurrencyWaitTimeoutMs)

  // 判定/落痕同源：库句柄直接取自 core
  const service: ManaJevService = {
    plugin: name,
    status: () => ({ plugin: name, wired: true, coreStorePath: core.storePath,
                     channel: config.channel, systemoneApiKeyEnv: config.systemoneApiKeyEnv }),
    judgeGuarded: (o) => judgeWithGuard({ ...o, guard,
                     judgeFn: o.judgeFn ?? (config.channel === 'systemone' ? systemoneDriver : ollamaDriver) }),
    guardState: () => guard.snapshot(),
  }

  ctx.effect(() => { const dispose = ctx.provide('mana-jev', service); return () => dispose() },
             'dsh-mana-jev: service')

  registerPassThroughPreStep(ctx, name)   // 必须调 next()，否则静默掐死下游
}
```

| **顶层构建** | 禁 workspace 级 build（会把他席在途码编进产物） |

⇒ **可行并行上限 ≈ 4 席**（3 席跑码 + 1 席跑判据类），且**必须**：① 写面两两不相交；② 每席只 build 自己那包；③ 遇锁等不等 kill；④ 基线重取只在收口窗口做。

### 37.2 依赖规则

```text
contracts 不依赖任何业务模块
services 依赖 contracts
services 之间通过事件通信，不直接 import 实现
apps 依赖 services
禁止循环依赖、跨模块数据库访问
```

✅ **本仓已落地并机检**：16 包 `inject` 声明（A0-5）+ R0 真 Loader 装配 16/16 + 卸载即净。

### 38.2 降级链路

> ⚠ **本仓口径与 v10 不同**：v10 的「兜底」列（向量相似度 / 模板回复 / 时间排序）**多未实现**；

| 组件 | v10 正常路径 | v10 降级路径 | v10 兜底 | **本仓实况** |
|---|---|---|---|---|
| JEV 判断 | JEV API | 缓存 → 本地规则 | 向量相似度 | **缓存 ✅ 已实现**（TTL 300s，仅正常判定且概率非 null 才进缓存）；**本地规则 ⛔ 未实现**；**向量相似度兜底 ⛔ 未实现** |

| 嵌入模型 | BGE-M3 自托管 | API 调用 | 关键词匹配 | ⚠ 本仓 `bge-m3`（1024 维）走 **OpenAI 兼容端点**；**关键词兜底 ✅** |

| 记忆注入 | JEV Injection Gate | 本地规则 | 不注入（沉默） | ✅ **fail-closed 已实现**：不注入**但必须留痕**（`degraded_unavailable`）；⚠ **「沉默」是被明令禁止的**（见下行纪律 1） |

**本仓真实的降级原因清单（可枚举、可按前缀统计）**：

| 前缀 | 条数 | 取值 | 归属模块 |
|---|---|---|---|
| `ollama-` | 6 | `request-failed` / `http-error` / `invalid-json` / `no-logprobs` / `no-candidates` / `no-yes-no-token` | `ollama.ts`（token 面） |
| `systemone-` | 8 | `no-api-key` / `request-failed` / `http-error` / `invalid-json` / `no-answers` / `primary-missing` / `primary-not-noul` / `invalid-probability` | `systemone.ts`（答案面） |
| `jev-` | 4 | `circuit-open` / `circuit-probe-in-flight` / `session-budget-exceeded` / `concurrency-timeout` | `framework.ts`（护栏面） |

**降级的三条硬纪律（本仓契约，非建议）**：

1. **禁止 `catch { return null }`** —— 降级**必须**落显式字段。
   反例就在本机生态里：守藏 `lib/vec.js:254` 原文 `catch { return null }` 把「provider 失败」与「正常空结果」混为一谈，
   后果是向量档**看起来跑通、实际全走词法**。
2. **「不可用」与「零值」必须可分辨**：概率不可用 ⇒ `null`（**不得用 0 冒充**）；判定失败 ⇒ `value:'unknown'`（**不得默认成 'no'**）。
   每一处降级必须**同时**给 `degraded: true` 与**非空** `reason`。
3. **降级不缓存**：网络类失败更**不得**缓存 —— 那会把一次瞬时故障**放大成 TTL 内的持续故障**。
   `unknown` 同理：宁可下次再问模型，也不把 unknown 当结论。

**向量路降级（与 JEV 路并列的另一条链）—— 三态明确、不是同义词**：

| `channel` | 触发条件 | `rankBy` | `degraded` |
|---|---|---|---|
| `'vector'` | 查询嵌入成功**且**至少一条候选常驻命中 | `'rrf'` | `false` |
| `'lexical'` | **调用方显式要求跳过向量**（本来就不走） | `'local_score'` | `false`（**不是故障**） |
| `'degraded'` | 嵌入失败（端点不通/维度不符/未配置）**或**候选常驻全未命中 | `'local_score'` | `true`（**想走但没走成**，必须留痕） |

> ⚠ **降级时 `rankBy` 必须是 `'local_score'`**：降级路径上没有 JEV 概率，若仍标 `jev_prob`，
> 下游会把「没判」读成「判了且低分」—— 这正是降级纪律要防的形态。
