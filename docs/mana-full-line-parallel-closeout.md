## 一、并发上限的**实测答案**（用户问题的正面回答）

**可并行 = 4 席写 + 1 席跑门。** 这是本会议**实测得出**的，不是主张：

| 约束 | 实测依据 |
|---|---|
| **跑门并发 = 1**，且**单实例锁在本 harness 下结构性失效** | `a0-check.mjs:139/:142` 双锁把两门压成一条通路；`ps` 实拍 `PID 1 = bwrap --unshare-pid --tmpfs /tmp`；**主持人独立复现**：调用 A 写 `/tmp/probeA.txt` 成功 → **调用 B `cat` 报 No such file** ⇒ 锁的活性锚点（`kill(pid,0)` + `/proc`）跨调用**看不见**持有者 |
| **产物内容腿 42s 窗口与 build 互斥** | `a1-check.mjs` 重编 16 包（实测 42073ms / 局部 12925ms），逐字节比 74 个产物 |
| **写面互斥** | 改 src ≤12；同文件 = 1；`core` 被 16 包 import ⇒ 独占波 |
| **基线闸与并行不相容** | `tools/.a0-10-baseline.json` 的 `expect=["docs/contract/"]` 是单写面快照；锚点 `66ef2bb` 后已有 22 件 packages 改动 |

⇒ **「能多少并发就多少并发」的正确落地方式**：4 条互斥写面并行 + **跑门单席跑、全席引用**（不靠锁，靠流程）。
