### 2.1 ✅ 已清：「有件无用」这一类（本会话战果）

| 处 | 形态 | 状态 |

### 2.2 ✅ V-1 已查清（K1 合并后实测）：整条链**贯通**，此前的"召回不到"是**评估器离线设计**

**K1 合并后实测**（`--online-embed --keep-tmp`）：
```
① vector 列真被生产填充：行数 7 | 已填充 6 | 最大 4096 字节（=1024 维 × 4）✅
② 召回读数从 degraded 变为 vector：
   eval-f0 q="根目录"  cand=2 ch=vector deg=false
   eval-f1 q="开源方案" cand=2 ch=vector deg=false
```
⇒ **K1 生效**（列被填充 + 召回改走向量通道），**§2.2 原先的疑问已答**。

**进一步实测（关键）**——语义相近 vs 无关的原始余弦：
```
"我不想用收费的软件"  cos=0.6216   ← 语义相近（词法腿查不到）
"我喜欢免费的东西"   cos=0.5409   ← 语义相近（词法腿查不到）
"量子纠缠退相干"     cos=0.3149   ← 真无关
```
⇒ 向量**本身区分得很好**（相近 ≈0.54–0.62 vs 无关 ≈0.31）。

**但** `vec.recall` 返回 `hitCount=1`（单候选恒命中），而 Recall Gate 报：
`gate='degraded'，reason="判定链可用但 1 条候选均未给出有限概率（vm1: trace-written-unknown(对方未提供 traceWritten 事实); vm1: downstream-degraded(no-judge-listener)）"`

**追因结论（实测，非推测）**：
- 判定链的**提供者**是 `packages/jev/src/index.ts:531`（`ctx.on('mana/jev/judge', …)`）；
- `attention` 是**调用方**（`ctx.waterfall('mana/jev/judge', …)`），不是监听者；
- 而**评估器把 jev 指向死端点** `127.0.0.1:1`（`tools/eval-l1-l4.mjs:201`，为离线可复现）
  ⇒ 判定必然降级 ⇒ gate 丢候选。
- **反证实验**：把 jev 改指真端点（`127.0.0.1:11434`）后 ⇒ `judged=1/1`、`gate=below_threshold`
  ⇒ **整条链贯通**（embed → store → recall → JEV 判定 → gate）。

⇒ **"向量腿语义召回失效"这个怀疑被推翻**：不是功能缺口，是**评估器刻意离线**使然。
⇒ 但暴露一个**真·未决问题**（见 §2.2b）：**评估器无法同时具备"可复现"与"判定链真跑"**。

### 2.2b ⚠ V-1b（新，真缺口）：判定链在评估里**从未被真跑**，故无判据

**实测两态**：
| 评估器状态 | jev 端点 | Recall Gate | 向量召回 |
|---|---|---|---|
| 缺省（离线） | `127.0.0.1:1` | `degraded`（no-judge-listener） | 查询结果**被 gate 丢弃** |
| `--online-embed` | 同上（**未同步改**） | 同上 | 同上 |

⚠ 即：**`--online-embed` 只开了嵌入，没开判定链** ⇒ 语义召回在评估里**仍然测不到**。
**真缺口**：本仓**没有任何判据**回答「判定链真跑时，语义相近的查询能否被放行」。
**推进动作**：给评估器加 `--online-judge` ⇒ **已做**（见下方 §2.2c 实测），
并把「语义召回」写成**独立读数**（离线报「未测」而非 0）。

### 2.2c ✅ 已实测（本轮）：向量腿有效，但**候选池由词法腿产生** ⇒ 结构性边界

**已落地**：评估器新增 `--online-judge`（jev 指向真端点）+ L2 新增**语义召回实验**读数。
离线报「**未测**」（**不报 0**，避免把"我们没测"读成"能力不行"）；在线出真读数。

**决定性对照实验**（真库真嵌入，同一记忆）：
```
查询「我不想用收费的软件」（与记忆不共享连续子串）
  ① 候选池 = 词法产出 → 词法命中 0 条 ⇒ 候选池空 ⇒ 向量腿 hit=0，gate=degraded(not-attempted)
  ② 候选池 = 手工放入该条  →               向量腿 hit=1，gate 有 probed=1
```
⇒ **向量腿本身有效**（②证明：给了候选就能命中）；
⇒ **但它拿不到词法查不到的候选**（①证明）——因为
`recallVector` 的候选池**只来自传入的 `candidates`**（`recall.ts:88-94`），
**向量腿不做全表扫描**。

⚠ **这不是 bug，是设计边界**（`recall.ts:109` 明写"候选池为空 ⇒ 没有可检索面，N=0 显式记 0，**不判降级**"）。
但它意味着：**「词法查不到 ⇒ 向量腿也查不到」** —— 而"语义泛化"恰恰要求**越过词法的候选面**。

**⇒ 这是本计划中优先级最高的一条真缺口（V-1c）**：
v10 §14.3 的混合召回若真要生效，**向量腿必须能自己产生候选**（稠密近邻检索），
而不是只在词法给的候选里重排。现状是**重排器**，不是**召回通道**。

**推进动作（需拍板，因为它改检索架构）**：
| 选项 | 内容 | 代价 |
|---|---|---|
| A | 向量腿自己产生候选（全表/近邻扫 `store`） | 改检索架构；需定"扫多少、用什么索引"；v10 §14.3 的语义面才真通 |
| B | 维持现状（重排器），如实登记该边界 | 零改动；但"语义召回"这句话**不成立**，须在所有文档/界面改口径 |
| C | 折中：候选池 = 词法 ∪ 向量 topN（预算受限的稠密扫） | 中等；能通语义面，但需定 N 与性能闸 |

⚠ **推荐 A 或 C**（B 会让"向量腿"名不副实）；**但此条改检索架构，属越权面 ⇒ 待你拍板**。

### 2.3 ✅ V-2 已勘察（结论：**架构选型差异，不是缺功能**）

**v10 §19 要求**（原文）：ITACL = 每轮内「观察→判断→检索→行动→反馈」循环，
含**嵌套状态机** —— 轮次级 `PRE_TASK → EXECUTING → VERIFYING → COMPLETED`、
执行步级 `PLANNING → ACTING → OBSERVING → JUDGING`、
判断分支 `CONTINUE / RETRIEVE / DIAGNOSE / COMPLETE`。

**实测（本席逐项 grep 12 个状态名）**：**全部零命中**（`packages/*/src`）
```
PRE_TASK 0 · EXECUTING 0 · VERIFYING 0 · COMPLETED 0
PLANNING 0 · ACTING 0 · OBSERVING 0 · JUDGING 0
CONTINUE 0 · RETRIEVE 0 · DIAGNOSE 0 · COMPLETE 0
```

**但对照既有面 —— ITACL 的三阶段**功能上都在**，只是**按事件摊开**而非显式状态机**：

| v10 §19 阶段 | 本仓落点（实测） |
|---|---|
| 一 任务前信息采集 | `agent/pre-step`（`attention` 的 waterfall，18 处 on/emit） |
| 二 执行中观察-反馈 | `mana/observation` + `mana/decision`（`core/src/event-types.ts:34/38`，**契约已冻结**） |
| 三 完成与固化 | `agent/turn-stopping` → 七链条（`chains.ts:334/342/404`） |

⇒ **结论**：本仓用**事件驱动**实现 ITACL 语义，没有把它做成一个**具名状态机对象**。
这不是缺失，是**选型**；v10 画的是状态机图，本仓允许等价实现。

**推进动作**：**不补状态机**（会与既有事件面重复且引入第二真源 —— 本仓明令禁止）。
⚠ 但**可做一件小事**：在 `chains.ts` 或契约档里加一段**对应表**（v10 状态名 ⇄ 本仓事件名），
让"ITACL 在哪"这个问题有**唯一归属地**可查。**属文档改动，低风险**。

### ~~2.3b 原判（已推翻）~~：先前"ITACL 未见独立落点"是 **grep 级判断**，现已逐项核实并给出上述结论。

**实测**：`grep -rl "itacl\|ITACL"` 命中 `long-term/src/write-gate.ts` 与 `prompts/src/index.ts` ——
那两处是**提示词/门禁引用**，**不是** v10 §19–§21 描述的那套「轮次内主动消费循环」状态机。

**但本席只做了 grep，未逐条核 §19 的状态迁移表** ⇒ 如实标 **未验证**。
**推进动作**：先做一张**只读勘察卡**（不写码）回答「ITACL 在本仓是什么形态、缺哪几态」，
再决定要不要补。**不在未勘察前开工**（本仓「含糊就先问」纪律）。
