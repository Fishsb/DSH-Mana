## 二、根本需求诊断（从目标能力倒推）

**V10 目标能力原文**：*「从编码到遗忘，从学习到调度，**完整模拟记忆的全生命周期**」*

**实测差距**：当前只有 **1.5 条链**在真实会话里流动（编码前段 → 注意力 → 注入），
**4 条链（巩固/再巩固/遗忘/学习）装配后无人消费**，且**没有任何东西在调度它们**。

### 根因三条（收敛）

| # | 根因 | 症状 | 为何它掩盖其他问题 |
|---|---|---|---|
| **A** | **没有「链的驱动者」** | 4 链零消费；`scheduler` 不调度七链 | 各链判据**全绿** ⇒ 「实现完成」与「系统能跑」在报告层面**同形** |
| **B** | **真 JEV 未启用** | `channel` 缺省 `'ollama'` = 本机 logprob **替身**（非 JEV 模型）；真 JEV(`jev-1.13`@`nano-gpt.com`) 凭据已在 `/jev/.env` 且实测可用 | 一切并发/批量优化都**打在替身上** |
| **C** | **LLM 生成层零消费** | `packages/llm` 全仓**零生产调用点**；8 项 LLM 能力 0 落点 | 没有生成能力 ⇒ 巩固/学习/遗忘的**内容侧**永远做不出来 |

### 真 JEV 实测（我本轮亲测，凭据来自 `/jev/.env`）

| 形态 | 实测 |
|---|---|
| 单问 | **2.32s** |
| **50 问 1 次请求** | **1.75s**（50 答案全回，比单问还快） |
| **120 并发** | **120/120 成功**，p50 2.35s / **p95 3.86s** / **26.1 req/s** |

⇒ **批与并发都有效且可叠加**：有效吞吐 = **N 问 × M 并发**。

## 六、诚实缺口（未验证，不得当 PASS）

- **DSH API 中转站的 120 并发未验证** —— 我实测的是 `nano-gpt.com` 真 JEV（120/120 成功），**不是 DSH API**（当前会话在用的那条）；W3 验收必须**首测**；
- `dshapi` 侧并发/限流策略未核（配置只有 `maxRetries: 20`，**无并发字段**）；
- `packages/llm` 是**纯转发层**（无重试/缓存/并发控制）⇒ W3-1 扇出层要**自带**这些；
- **A0 门当前无读数**（`exit 4` 拒绝给结论）；
- 本方案**未评估生成质量** —— 8 项能力只有**通道**，质量需首测后自设基线；
- 1.1 表的「已实现 24 项」按**非注释代码命中**判定，**未逐项端到端实跑**（W1 的验收正是补这一课）。
