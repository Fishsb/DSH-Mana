# 方案 §14 十条故障模式的可观测性落点（A0-9）

> **为什么有这一档**：方案 §14 的「检测方式」列经逐条判定为 **真有信号 0 条 / 半真 3 条 / 愿望 7 条**
> （《落地册》§2 G2）。本项目**只有一名使用者、没有「用户报障」通道** ⇒ **测不出来的失败就是永久静默失效**。
> 故每条故障模式在此**必须给出表/字段名落点**；给不出即标「**不可观测**」并挂账，不得写「监控」了事。
>
> **落点口径**：`表.列` = 阶段 0 已冻结的存储面（`packages/core/src/schema.ts`）；`判据ID` = 《落地册》§4 的机检判据。
> **状态**：`✅ 真信号`（有确定落点且可机检）/ `🟡 半真`（有落点但需先造工况）/ `⛔ 不可观测`（挂账）。

| # | 故障模式 | 方案原「检测方式」 | 本册落点（表.列 / 判据） | 状态 | 实现阶段 |
|---|---|---|---|---|---|
| 1 | JEV API 超时 | 超时计时器 | `jev_log.latency_ms` + `jev_log.degraded`；判据 **A1-8**（Write→`gate in (unavailable,budget)`）/ **A1-11**（`degraded===true` 且 `gate` 非空） | ✅ 真信号 | 阶段 1 |
| 2 | JEV 误判 | 审计日志对比 | `jev_log.result_value` + **`verdict`/`verify_state`**（阶段 3 增列，§18 映射要求**误判率与核验覆盖率同时暴露**，否则「0% 误判」与「从未核验」同形） | 🟡 半真 | 阶段 3 |
| 3 | 向量库不可用 | 健康检查 | `mana/recall` 事件的 `channel='degraded'` + `degraded` 字段；判据 **A1-11**（排序依据须为 `local_score` 而非 `jev_prob`） | ✅ 真信号 | 阶段 1 |
| 4 | SQLite 锁竞争 | 重试计数 | **无可数之处**（`node:sqlite` 无重试计数 API）⇒ 记 **`mana_trace` 的 `mana/plugin/inactive` 行 + 开库器 `busy_timeout` 读回值**为**替代观测**，并在阶段 1 补一次「并发写失败」负例 | ⛔ 不可观测（部分替代） | 阶段 1 |
| 5 | 插件加载失败 | Cordis 加载日志 | `mana_trace` 的 `mana/plugin/inactive` 行（`payload.id` / `payload.missing`）；验收口径改为「**最近 N 分钟内无 inactive 记录**」 | ✅ 真信号 | 阶段 0（事件已冻）/ 阶段 2（生产） |
| 6 | 工作记忆溢出 | token 计数 | `mana/working-memory` 的 `capacityChunks` 配置 + `mana_trace` 的注入行数；**注入块字符数**落 `inject_log.block_id` 关联的块长度 | 🟡 半真 | 阶段 1 |
| 7 | 记忆爆炸 | 存储监控 | `store/snapshot` 探针（**判增速不判绝对值**，§18 映射）；阶段 3 `long-term` 落库行数随时间序列 | 🟡 半真 | 阶段 3 |
| 8 | 前缀缓存失效 | 缓存命中率 | ⚠ 方案 §13.2 的「缓存命中率 >40%」**未指明是哪个缓存**。本册限定口径为 **`jev_log.cached`**（TTL 300s 的判定缓存）；**LLM 前缀缓存全文无落点** ⇒ 若 `ctx.llm` 取不到命中信息，**如实标不可观测** | ⛔ 不可观测（前缀缓存面）/ ✅ 真信号（JEV 缓存面） | 阶段 1 |
| 9 | 输入截断 | 输入长度检查 | `jev_log` 增列 **`input_chars` + `trimmed`**；**红灯样本 = `trimmed=1 且 verdict=DROP`**（§18 映射原话） | 🟡 半真 | 阶段 1 |
| 10 | 用户模型漂移 | 精度监控 | `user_model_history` 追加表（A4-4）+ 「30 天内改 ≥3 次」判漂移候选；⚠ **须阶段 0 预留表结构** | 🟡 半真 | 阶段 4 |

## 统计（A0-9 的机检口径）

| 状态 | 条数 |
|---|---|
| ✅ 真信号 | **3**（#1 / #3 / #5） |
| 🟡 半真 | **5**（#2 / #6 / #7 / #9 / #10） |
| ⛔ 不可观测（含部分替代） | **2**（#4 / #8） |

> **与方案原状的对比**：原「检测方式」列 **真有信号 0 / 半真 3 / 愿望 7**（G2）；
> 本档把可观测者提升到 **真信号 3 + 半真 5**，其余 **2 条明确标不可观测并挂账**，
> 而不是继续写作「监控」「健康检查」这类**给不出落点的愿望**。
>
> ⚠ **两条不可观测项不得静默通过**：
> · **#4 SQLite 锁竞争**：`node:sqlite` 不暴露重试计数 ⇒ 只能以「开库即设 `busy_timeout`（默认 0 会立即失败，G7）」+ 负例测试替代，**这是替代观测，不是原判据的达成**。
> · **#8 前缀缓存**：属 LLM 提供商侧能力，宿主不暴露命中信息 ⇒ 按本仓纪律**不得用代理量当判据**（笔记「代理指标非判据」），如实挂账。
