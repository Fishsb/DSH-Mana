## 3. 收口 1：`librarySize` 口径 —— 裁定 = **改名（不是改值）**

### 3.1 先读 core 改后的实现（派单要求）

`packages/core/src/index.ts:243-248` 的接口注释 + `:521-533` 的实现：

```ts
// :244  库中**活记忆**条数（`retired = 0`），判「库非空」用，使 `reason` 可被交叉核对。
const librarySize = Number(
  (opened.db.prepare('SELECT COUNT(*) c FROM memory_items WHERE retired = 0').get() ...)
```

⇒ **core 的 `librarySize` = 活记忆数**；它的唯一消费者是 `:550-551` 的
`rows.length > 0 ? null : librarySize === 0 ? 'empty_library' : 'ok'`。

### 3.2 本包那个同名字段**不是同一个量** ⇒ 改名

`packages/long-term/src/retirement.ts`（改前 `:330`）：`librarySize: counts.total`，
而 `countMemories`（`:195-201`）的 `total` 是 `SELECT COUNT(*) FROM memory_items`（**不设 WHERE**）。

**二选一的依据（三条，逐条可核）**：

1. **它统计的是"表里一共有多少行"这个不同的量** —— 派单给的判据原文即「若它统计的是『表里一共有多少行』
   这个**不同的量**，那就该**改名**而不是改值」。`total` 含已退休行，core 的 `librarySize` 不含。
2. **改值会产生冗余副本**：本包**已经**有 `liveSize: counts.live`（`:331`）。若把 `librarySize`
   也改成 `counts.live`，则 `librarySize === liveSize` **恒成立** —— 同一个读数占两个字段名，
   正是本仓「同一条事实两个归属地」。改名则两条读数各归其位。
3. **core 那次实害在本包不存在**：core 的假红来自"分母被当判据用"；本包 `reason` 的分母是
   `counts.live`（`:346`），与 `librarySize/totalSize` **无因果**。本字段实际是**库规模读数**
   （软删除不变式的取证：`SoftDeleteOutcome.rowsBefore/rowsAfter` 取的就是 `counts.total`）。
   ⇒ 改它的**值**会造出一个语义更弱的副本，改它的**名**才让两个量各自可读。

**故：`librarySize` → `totalSize`**（改后 `retirement.ts:117` / `:345`），并在字段注释里
显式写出「为什么不叫 librarySize」、恒等式 `totalSize === liveSize + retiredSize`、以及与 `reason` 无因果。

### 3.3 新增机检 ⑦（`retirement.test.mjs:352-425`）

夹具 =「**4 条，其中 1 条 `retired=1`**」（3 活 + 1 退休），走**生产路径**灌入
（`core.writeMemoryItem` + `retireMemory`，非测试直写 INSERT）。

- **前置控制**：`assert.notEqual(physicalRows, liveRows)` ——
  两读数相等时"口径写反"根本测不出来（**防平凡通过**）。
- **独立测量**：期望值由 `db.prepare('SELECT COUNT(*)…')` 另取，**不信被测函数自报的计数**。
- 断言四件：`totalSize === 4`、`liveSize === 3`、`retiredSize === 1`、
  **恒等式 `totalSize === liveSize + retiredSize`**、`assert.notEqual(totalSize, liveSize)`。
- **reason 的反向腿**：3 活时查不到 ⇒ 必须 `'ok'`；再退休到 0 活 ⇒ 必须 `'empty_library'`
  （全表仍有 4 行）—— 两个方向都可分辨，钉住"分母是 liveSize 而不是 totalSize"。

## 5. 收口 3：口径注释 ⇄ 实现 一致性腿（`retirement.test.mjs:427-560`，用例 ⑧）

派单允许「做不到就如实说」。**我判断：做得到，但必须换一种写法** —— 且我**没有**写成"数注释"。

### 5.1 为什么不做「断言注释里出现过某词」（本仓点名的假腿形态）

那种写法**恒真**：改了实现而注释原样留着，子串照样命中 ⇒ 正是它声称要防的形态却抓不到。
**故本腿让注释去决定期望值**：

1. 从源码抽出紧邻 `totalSize` 字段声明的块注释（`retirement.ts`）；
2. `classifyScope()` 判出口径（`physical` / `live` / `undeclared`）；
3. 用**独立测得的**行数算出该声明**应有的取值**；
4. 断言实测值 == 期望值 ⇒ **声明或实现任一侧漂移即红**。

### 5.2 分类器的自检（防它退化成恒绿/恒红）

- `'活记忆数'` ⇒ `live`；`'全表物理行数（含已退休）'` ⇒ `physical`；`'就一个数'` ⇒ `undeclared`；
- ⚠ **负控要能真否证**：`'不含已退休的行数'` ⇒ **`live`** —— 子串里含「含已退休」，
  按子串直判会**把相反的声明读成同一个**。故显式优先匹配否定式（本条即派单点名的
  「若负控本身恒真（includes 判『可做』而『不可做』包含它），那是假覆盖」形态）；
- 两者都出现时 ⇒ **首个声明胜出**（注释引述对面口径作对比不得让本方声明失效）。

### 5.3 负向对拍（三个方向，全部实测报红）

| 扰动 | 实测 |
|---|---|
| **注释漂移**（`全表物理行数（含已退休）` → `活记忆数`） | `assert.throws(...)` ✅ 报红 |
| **实现漂移**（`value: measured.live`） | `assert.throws(...)` ✅ 报红 |
| **删掉口径声明**（`undeclared`） | `assert.throws(...)` ✅ 报红 |

这三条与 §3.4 的扰动 A/B 是**同一批红**（改 `totalSize` 的取值时 ⑧ 一起红，已在 3.4 表中实测）。

### 5.4 效力边界（如实写，不夸大 —— 不许冒充它做到了做不到的事）

本腿**不**证明：① 口径变更**是否合理**（注释与实现**一起**改成同一个新口径 ⇒ 照绿；
那是刻意的口径变更，属评审范围，不是"忘改注释"）；② 注释的可读性/完整性。
它只判「**声明与行为是否同向**」＝ 抓**单侧**漂移。

`domain.ts` **不在本席写面**（归契约席）⇒ **一字未动**（派单明令）。
