## 三、反证判据

### R5 产物侧落点（**不照抄 R1-b 端点**）
- **落点**：Client 每次渲染 ⇒ 经协议 `mana-ui/render` 向 Host 追加一条 `mana_trace` 的 `ui/render` 行（`store.ts:writeRender`，唯一写口）。
- **正向**（`R5①`）：装载态渲染一次 ⇒ `ui/render` 计数 `before+1`，回执 `traceSeq>0`。
- **反证**（`R5②`）：走**真 cordis Loader** 按包名装上 `dsh-mana-ui` ⇒ `ctx.get('mana-ui')` 可读 ⇒ 撤 loader entry + 撤协议路由 ⇒ **服务不可读** ⇒ 同一触发 **0 新行**，且回执 `degraded:true / reason=/路由不可达/`。
- **库**：`mkdtempSync(tmpdir(),'mana-ui-r5b-')` 临时库，**全程不触碰 `$DSH_HOME/memory/mana.db`**。

> ⚠ **对拍③ 第一轮失败（值得记的过程）**：首轮我把扰动打进 `src/client/host.ts`，判据**没报红**。这不是判据松，是**我打错了对象** —— 判据原文是「对 client **产物** grep」，被测对象是 `lib/client.js` 字节；只改 src 不重建，产物根本没变。改打产物后如实报红。**判据是对的，是我瞄错了靶**。

### 「审计回放不写库」怎么证（**这条是本席的判据设计重点**）

三层，**互不顶替**，强弱边界写清楚：

1. **库镜像逐字节比对**（`A5-3③`，独立证据）：回放前后对 `memory_items` 取 `SELECT *` 全行 JSON 的 **sha256** + 行数，**两者都必须不变**。先经生产侧 `core.writeMemoryItem` 落 2 行（**不是夹具直写**），回放**同时走纯函数与协议端点**两条路，再比对。
   - 为什么比哈希而不只比行数：**`UPDATE` 改一行不改行数**，只数行会漏掉写回。
2. **写目标清单交集为空**（`A5-3④`）：`ReplayFrame.scanTargets` **恒为 `[]`**，与 `STATE_REPLAY_WRITE_TARGETS = ['memory_items']` 的**交集必须为空** —— 把语义冲突做成一条断言，不是一句注释。
3. **★负扫探针**（`A5-3⑥`，最硬）：对 `panel.ts / store.ts / replay.ts` **扫 SQL 写语句**（`INSERT/UPDATE/DELETE/REPLACE/DROP`），断言目标表**不含 `memory_items`**；且探针**自检**「必须真扫到 ≥1 条语句」并断言写口清单**逐字等于** `['src/store.ts:INSERT→mana_trace']`。
   - 这条问的不是"回放面自称什么"（那是自我声明），而是**这段实现有没有写掉记忆表的能力**。

> **强度边界（写在明处）**：`scanTargets` 是**回放面自报**字段；它约束的是"经本模块表达出来的写回"。真正的独立证据是第 1 条的库镜像比对。两者是**冗余**，不是互相顶替。
