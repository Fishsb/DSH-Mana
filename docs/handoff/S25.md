## 5. 未决项

1. **`A1-12` 真机腿抖动（本席实测，非本席造成）**：同一脚本相邻运行，一次
   `归因=TIMEOUT_AFTER_CONNECT（TCP 4ms 成功 ⇒ 服务在本端口上；嵌入 30155ms > timeoutMs=30000）`
   判 FAIL，另一次 `归因=OK（嵌入 4402ms）` 判 PASS。服务侧同时刻 `GET /api/tags HTTP=200 t=0.07s`

   同源抖动（实测其 duration 达 **18.8s**，逼近超时）。
   **[建议决策] 该腿要不要把「测量条件不具备」与「真失败」分开判** |
   选项：**A** 维持现状（红即红，靠 detail 归因）**B** 把 `TIMEOUT_AFTER_CONNECT` 降为挂账
   **C** 只把「TCP 连不上」判红、超时判挂账 | 推荐：**C** 理由：现有 detail
   已能分辨两类（`归因=` 字段），缺的只是**不判红**的口径；C 比 B 更保守（真不可达仍红）。
   ⚠ 本席**未自行改档位**（属拍板面）。
2. **[建议决策] `ARTIFACTS` 该不该有「原定验收阶段」** | 选项：**A** 维持「待补」+ 在本册 §3.1
   补一行「产物新鲜度 = 各批次构建前置」**B** 给它立一条独立验收条（含阶段号） |
   推荐：**A** 理由：它是横切前置而非某阶段交付物；补一行口径即让「待补」变成「有出处」，
   比新造一个阶段号诚实。
3. **`--json` 的 `itemSet.actual` 已并入 `itemSet.seen`** —— 若有仓外消费者读 `actual`
   会取到 `undefined`。仓内已验证无消费者（`a0-check` 读的是**人读输出**的「实测 N 项」文本，
   不是 JSON 字段）；本席**未补 `actual` 别名**，避免两名字两真源。
4. **`--self-test` 的 `c16pattern` 只做「副本 == 原文正则」**：C16 若被整体**删除**，
   本腿报「未判定」（挂账）而非红 —— 「判据被删」与「判据改名」在本腿看来同形，
   需文档侧给定锚点才能分开。
5. **`A0-10` 的写面机制缺口（本席实测踩到，值得单列）**：该腿的「声明写面」来自
   `--record-baseline --expect`，**不自动包含当轮在场的所有席** ⇒
   任一新席只要没被写进那次 `--expect`，它的改动就会被列成「**无主脏**」。
   ⇒ 多席并行时这会**把正常改动报成越界**（假红），且**越界的真改动会被同一形态掩埋**。
