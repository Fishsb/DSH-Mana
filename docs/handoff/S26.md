### 本席踩到并修掉的两个**静默假绿**（都是"对拍看上去在跑、其实没牙"的形态）

**① 嵌套 `node --test` 的 `NODE_TEST_CONTEXT` 继承**（首次实测：五条对拍**全部 exit 0**）
· 机理：Node 的 test runner 给每个测试子进程设 `NODE_TEST_CONTEXT`；子进程带着它启动会走"测试子进程"分支 ⇒ **不执行任何用例、exit 0、零输出**。对拍侧看到的"扰动后仍然绿"是**完全静默的假绿**。
· 处置两条都做：`env` 显式剥掉该变量；且**不信退出码本身** —— 解析不到 TAP `# tests N` 一律记 `code:-1`（**不是 0**）。
· 常驻腿：`negatives.test.mjs`⑤ **现场复现**两种情况（清洗后有计数 / 带着它零计数 exit 0），Node 行为一变即报红。

**② 改真源与并行测试的竞态**（首次全量跑得 `# pass 24 / # fail 5`，其中报出 `episodic 实测 1801000` = **扰动值**）
· 机理：`node --test` **并行**跑多个用例文件，而第一版对拍改的是**共享真源** `src/params.ts` ⇒ 并行着的 `window-boundaries.test.mjs` 读到**扰动到一半的值** ⇒ **假红**。
· 若把它当成"对拍成功"，拿到的红其实来自别的文件读到半路状态 —— **证据是假的**。
· 处置：扰动迁进 `/tmp` 沙箱副本（软链仓内 `node_modules` 保裸包名解析，同时拷真 `core` 源码）⇒ 真源从未被打开写。
· 复跑证据：改后**连跑 3 次全量，均 29/29 pass**（消除竞态后无 flake）。
