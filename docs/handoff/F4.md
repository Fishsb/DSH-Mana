## 5. 未决项 / 缺陷报告（**本席不改 src，报主持人派单**）

### [缺陷-1] `working-memory.budgetChars` 是**零消费死开关**（会让失败不可观测，**排最前**）
- **位置**：`packages/working-memory/src/index.ts:45`（接口）、`:50`（Schema 缺省 4000）、`:116`（**唯一读取点**，仅回填进 `snapshot().budgetChars`）。
- **实证**：`budgetChars=1` + 4 块 × 5000 字 ⇒ `snapshot() = {budgetChars:1, chars:20000, over:19999, evicted:0, size:4}`（`/tmp/f4-budget.mjs` 实跑）。**超预算 19999 字，无截断、无逐出、无记账。**
- **反向对照**（排除"配置整体没接上"）：**同一组配置**下容量轴确有闸 —— 缺省 4 块时第 5 块必逐出并记 `evicted=1`（W1 实测）。⇒ 是**该单键**零消费，不是配置面失效。
- **性质**：与 `S0` 的 `autoMigrate`、`S22` 的 `failWhenUnconfigured`、`long-term` 的 `enabled` **同族**（"声明了却不产生可观测差异 = 死开关"），本仓既有处置是**改真闸或删除**。
- ⚠ **已披露 ≠ 可放过**：该项曾在 `docs/handoff/S-verify2.md:376` 被越界上报过，但**至今未处置，且源码里无「尚未实现」标注** —— 用户以为设置页那个数值框在管预算，其实没管。
- **判据面处置（本席已完成的部分）**：W5 已断言 `snapshot()` 结构含该键、`chars` 按**码点**计且与逐块求和一致，使"有这个键"与"这键在管什么"**可分辨**；**未**为它写"超限即截断"的断言（那会写出一条对当前实现**必红**的判据，需先拍板语义）。

### [缺陷-2] `perception.maxChunkChars` / `chunkOverlapChars`：**同族可放过**
上述越界上报把这两键与 `budgetChars` 并列，但**本席实测它们有真行为**：`maxChunkChars:8` ⇒ 20 字输入切 3 块并**逐块落库**（P1 逐字核对 `['01234567','6789ABCD','CDEFGHIJ']`）；改 `4/0` ⇒ 切 3 块 `['0123','4567','89']`（P2）。**⇒ 报告需更正：这两键不是零消费**（`S-verify2` 的静态 grep 未发现 `perceive` 内部的消费点，属**假阳性**）。
⇒ `attention.jevThreshold` / `metacognition.confidenceTarget` **不在本席写面、未验证**（不越界下判）。

### [未决-3] `capacityChunks = 0` 的语义未在契约里定义
实现在 `index.ts:101` 用 `config.capacityChunks > 0 &&` 短路 ⇒ **0 = 该轴不设闸（无上限）**，5 条全留、`evicted=0`。W3 已**如实钉住现状**（不判缺陷）；但"0 = 无限"与"0 = 全不放行"是两种合理语义，**契约未写**。
- `[建议决策]` `capacityChunks <= 0` 的语义 | 选项：(A) 明订为"该轴不设闸（无上限）"，与现有实现一致，仅补契约文字 / (B) 改为"容量 0 = 一条都不收"，实现与 W3 判据同步改 | 推荐：**A** 理由：与仓内既有约定同族（`maxRounds=0` / `maxTokens=0` 皆为"该轴不限制"），且改 B 会让"配置漏填"退化成静默全丢。

### [未决-4] `budgetChars` 的处置方式（与缺陷-1 配套）
- `[建议决策]` `working-memory.budgetChars` 处置 | 选项：(A) 落成**真闸**：超 `budgetChars` 时截断/逐出并**显式记账**（新增 `budgetEvicted` 字段），本席随后补对应判据 / (B) **删除**该配置项（与 `long-term.enabled`、`failWhenUnconfigured` 同处置） | 推荐：**A** 理由：本包文件头第 8–10 行**已自述**"容量上限必须是真闸……否则'容量管住了'与'根本没管'表面同形"，同一理由原样适用于 budget 轴；且 `attention.injectionBudgetChars` 已有同语义真闸先例可对齐。

## 7. 结论回答派单的两处提问

- **⑦ snapshot 顺序敏感吗？⇒ 敏感（FIFO）**。判因（先读实现）：`working-memory/src/index.ts:98` push 到**尾部**、`:102` `shift()` 从**头部**逐出 ⇒ 数组顺序 = 到达时序（`idx 0` 最旧、末位最新）。W5 已按此断言（`seq=[1,2,3]`、末位=`req-3`），并另断 `map(c=>({...c}))` 的**深拷贝**隔离。
- **两包实现是否真有缺陷？⇒ 有 1 条（`budgetChars` 零消费，见缺陷-1）+ 1 条语义未定义（`capacityChunks≤0`，见未决-3）**。除此之外**未发现**：`chunkText` 边界无漏（含空串/单字/恰满/超一/超长/overlap 越界上下界）、`evicted` 记账精确（条数+内容逐项）、`observation` 事件与落库一致、卸载即净成立。
