━━ 9. 追修（主持人派单 · 2026-09-26 09:0x）：jev channel 缺省翻转的连带影响 ━━
现象：W1-2 席把 jev 的 channel **缺省**由 `ollama` 翻转为 `systemone`
  （packages/jev/src/index.ts:139；与其 src mtime 08:54 一致）。
  本包 tests/recall-gate-jevlog.test.mjs 的两条腿（RG-JL-⑥c / RG-JL-Q1）随之由 12/12 变 10/12，
  reason 含 `downstream-degraded(systemone-no-api-key)` ⇒ 判定改道真通道、本机无 key 即降级。
根因（本席独立复核，不采信单方报告）：那两条腿的 jev 挂载点写的是 `ctx.plugin(jevMod, {})`
  —— **未声明通道** ⇒ 取**全局缺省**。而"替身通道的确定性生产桩"这一立意
  （自挂监听器注入 fakeFetchYes 且显式传 channel:'ollama'）在缺省翻转后**悄悄改道**：
  判据的红绿不再由本用例要测的生产侧决定，而由别人的缺省值决定。
  ⇒ 属"测试夹具依赖全局缺省"的形态缺陷，**不是 w1-2 的 bug，也不是本席 W1-3 的 bug**。

处置（**只改夹具、不动 src 语义**）：
  · 受影响的两个 jev 挂载点（⑥c / Q1）改为 `ctx.plugin(jevMod, { channel: 'ollama' })`
    —— 显式声明替身通道，语义不依赖全局缺省。
  · ⚠ **另两个挂载点未动**（第 124 行 = 挂载工厂，无 jev；第 404 行 = ★ 反向腿**故意**让下游抛错；
    **第 364 行 = ⑥b 腿故意用不可达端点测降级**）—— 后两条的红绿**本就该**随缺省走，
    把它们也钉成 'ollama' 会**削弱**其覆盖面。只改"被缺省翻转打破"的那两处 = 最小改动。
  · **加显式通道自证**（两处）：`ctx.get('mana-jev').status().channel === 'ollama'`。
    理由：显式声明**本身不会被机检** —— 若哪天有人把这行改回 `{}`，或 jev 侧改 channel 语义，
