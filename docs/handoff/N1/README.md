# N1 · 实测报告：`_freeze` 锚点/跃迁两腿为何**收不了口**（2026-09-26）

> **一句话结论**：任务书要求的「重取基线 ⇒ 两腿回到可枚举」在本仓**结构上不可达** ——
> 两处报红都位于**流水内部**，而 record 只能**追加在末尾**。
> 唯一能让它们消失的动作是删除/改写 `seq=16`，而那正是本卡与全仓明令禁止的**篡改流水**。
> ⇒ 本席**拒绝执行重取**，改为如实登记 incident + 留下可复算的反证。

## 二、成因（任务书第 2 条）

读 `docs/contract/_freeze.log` **seq=16 / 18 / 19**：

- **seq=16**（record，`head=a17daf4`）：主持人反证测试期间记的中间态基线；
- **seq=18**（incident）：反证测试留痕 —— 造了两个写面外探针并提交（a17daf4、3b7f9a5），
  证明跃迁腿**确实有牙**，随后 `git reset --soft` 回退探针提交；
- **seq=19**（incident）：`git reflog expire + gc --prune=now` 回收了 a17daf4/3b7f9a5 两个对象 ⇒
  **seq=16 仍引用已被回收的锚点**。

⟹ 锚点腿 = 「顺序合法」腿，遇到 `1963e88 ⊄ a17daf4`（对象已不在历史）即报回退；
跃迁腿 = 「区间内容合规」腿，读该区间时 `git diff` 抛错 ⇒ 具名 note「区间不可枚举」。

**判据行为正确**：`tools/a0-check.mjs:1117` 把「锚点已被抛弃」写作**具名 note** 并由 `leapBad` 判红
（`note ? true : out.length > 0`）⇒ 作者**预先设计**了「锚点消失」这一状态，且设计为**如实报红而非静默通过**。
seq=19 的判定与本轮实测一致。

## 三、决定性反证：重取基线**无效且有害**（任务书第 3 条 —— 本席据此拒绝执行）

> 实验位置：**隔离副本**（`git clone`），主仓与 worktree **零改动**。所有读数同对象库、同 checker(md5 `6baaf3c8e797`)。

### 3.1 重取无效（决定性）

锚点腿/跃迁腿比的是**相邻两条 record 对**。两处报红对**都在流水内部**；
新 record 只追加在**末尾** ⇒ **往末尾追加不会移除中间已有的对**。

| | 锚点腿 | 跃迁腿 |
|---|---|---|
| 重取前 | 锚点回退（第 12→13 条） | 6 段（含 2 段「区间不可枚举」） |
| 重取后 | **逐字不变**（同上） | **7 段**（2 段「区间不可枚举」**仍在**） |

⇒ 唯一能消除这两处报红的动作是**删除或改写 seq=16**。**故本卡验收标准 2 在结构上不可达。**

### 3.1b 反证加强：**即使把被回收的对象找回来，锚点腿照样红**

为排除「只要恢复对象就能收口」这一条退路，本席做了对照实验：
把 seq=16 的 `head` 换成 **8a2bfae**（一个**真实存在的、且以 1963e88 为祖先**的后继提交）——
等价于「a17daf4 从未被 gc 回收、且当时就落在合法后继上」这一最有利的情形。

| 情形 | 锚点腿 | 跃迁腿 |
|---|---|---|
| 现状（对象已回收） | 锚点回退（**第 12→13 条**：1963e88 ⊄ a17daf4） | 6 段 |
| 对象「已恢复」 | 锚点回退（**第 13→14 条**：8a2bfae ⊄ 1963e88） | 5 段 |

⚠ **锚点腿仍是红**，只是报的**位置换了**（12→13 变成 13→14）。
成因：seq=16 的锚点**根本不在 1963e88 之后**（seq=17 又记回 1963e88），
所以「1963e88 → seq16 → 1963e88」这个**来回摆动**在锚点腿下**恒为回退**，
与对象是否可达无关。⇒ **恢复对象不解决问题**（且对象实际已不可恢复：
`git fsck --lost-found` 无该对象、仓**无 remote** 可回取）。

### 3.2 重取有害：会**新增**一段越界

`seq=20` 声明的写面不含 `package.json`，而 `8a2bfae→现 HEAD` 区间内 `6d3762f` 改了它：

```
$ git diff --name-only 8a2bfae..3c6eb64
README.md · docs/contract/_freeze.head · docs/contract/_freeze.log · package.json
packages/prompts/src/__verify_mask_probe.ts · packages/vector/tests/gate.mjs · packages/vector/tests/recall-graph.test.mjs
$ python3 判定 package.json 是否落在 seq=20 写面内
package.json -> *** OUT OF FACE ***
```

⇒ 新 record 落盘即**新增一段越界**（实测 跃迁腿 6→7 段）。
要让它不红，只能把 `package.json` 写进 `--expect` —— 那是**别席已提交的产出**，
声明成自己的写面 = **伪造写面**（本仓明令禁止「把 --expect 声明成全集」），
且会**永久遮蔽**该文件后续的写面外改动。

### 3.3 隔离 worktree 下重取会**造假红**

三件套的 `at` 取自**记录时刻**，而 git 在 merge/checkout 时会**重写 mtime**；
时序腿判据为 `mtime > at + 1500ms`（`a0-check.mjs:1046`）。

```
实测 A（新检出）：worktree 内三件套 mtime = 检出时刻 ⇒ 时序腿报「记录之后仍被写过：+4639s」
实测 B（延迟 6s 合并）：files.txt/head 的 mtime 比 record.at 晚 6101ms ⇒ 时序腿假红
```

⚠ **该假红由「检出/合并」动作本身造成，不是篡改。** ⇒ 在隔离 worktree 里重取三件套再合并，
会**亲手创造一条假的「写了又回滚」证据**。

## 四、本席实际做了什么

1. **不重取基线**（理由见上：无效 + 有害 + 会造假红 + 需伪造写面）；
2. **追加一条带日期的 incident**（seq=21，append-only，**零篡改历史条目**）；
3. **处置无主未跟踪件** → `docs/handoff/N1/untracked-ownership.md`（28 件逐件归属）。

### 4.1 incident 追加是**腿中立**的（实测）

| 腿 | 追加前 | 追加后 | 同 |
|---|---|---|---|
| 流水腿 | 末条 seq=20 …（另有 **5** 条 incident） | 末条 seq=20 …（另有 **6** 条 incident） | 仅计数 +1（预期） |

| 时序腿 | **记录之后仍被写过**：sha256(+4639s)、fi… | **记录之后仍被写过**：sha256(+4639s)、fi… | **是** |
| 跃迁腿 | 6 段越界：cbd80f7→16b666 | 6 段越界：cbd80f7→16b666 | **是** |

⇒ incident 除「incident 计数」与「末条 record **仍**指向 seq=20」外，**任何判定腿不变** ——
证明「人可读留痕」与「机器指纹比对」**互不污染**（与 seq=6/11/15/18/19 的既有体例一致）。
