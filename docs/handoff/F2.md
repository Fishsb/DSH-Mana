## 三、反证判据（负向对拍 N1–N5 · 每条打一个靶）

**靶位说明**：判据经 `ctx.loader` 按包名解析到 `packages/attention/lib/index.js`；
故对拍**一律改写 lib 文本并在临时目录装载** ⇒ 天然打在判据真正读取的那一层
（在 `src` 上改字而不重建会被 `ctx.loader` 完全绕过 ⇒ 那是「对拍打错靶」）。
**仓内零写入**：每条对拍前后各取一次 `judgedSurface()`（src + lib + core lib 的 sha256）并断言**逐字节不变**。

| 编号 | 变异（`lib/index.js` 内） | 预期必红 | 实测 |
|---|---|---|---|
| **N1** | `finish('reset')` → `finish('skip_no_candidate')` | 该类不可达（G1-⑤/G1-⑥） | ✅ 变异后 `reset` 不再出现，且被换成的枚举真出现 |
| **N2** | 两个 fail-closed 闸 → `if (false) {` | 降级时照常注入（G2-①/G2-③） | ✅ 降级场景下反而写 `injected`、`degraded` 列变 0、块真塞进上下文 |
| **N3** | `const downstream = await next();` → `= undefined;` | 下游收不到（G3-④，**G9 核心**） | ✅ 下游 0 次、**无异常**、**宿主本步消息被整批吃掉** |

| **N5** | 预算闸 → `if (false) {` | 截断腿（G4-③） | ✅ 超限不再截断，长内容完整入块 |

### ⚠ 对拍过程中**实测纠正**了本席的两处预设（如实记）

1. **N3 的后果比预设更糟**：预设是「waterfall 返回 `undefined`」。实测：变异体仍返回
   `{kind:'enter', messages:[注入块]}` —— 它把 `downstream?.messages` 当成了空数组，
   **于是宿主本步送进来的消息一条都不剩**。⇒ 「不调 `next()`」的真实形态是
   **把宿主这一步的输入整批吃掉**，而不是"少做一件事"。断言已按**实测**改写。
   （位点：`src/index.ts:310` + `:454` + `:481-485`）
2. **「下游」的注册序有方向**（本席用真 waterfall 实测）：cordis 的 `waterfall()` 把监听器表
   `shift()` 出来逐个调用（**先注册者先执行**），**没调 `next()` 的监听器否定整条链**
   （`cordis/lib/index.js` 的 waterfall 注释原文：*a listener that does not call `next()`
   vetoes the rest of the chain, including the built-in behavior*）。
   ⇒ 「被掐死的下游」= **本包之后注册**的监听器。
   ⚠ 本席**第一版夹具把哨兵注册在包之前**，读数恒为 `reached=1` —— 那是**假覆盖**
   （哨兵在更外层，永远轮不到它被掐）。此坑记在此，防后人重踩。

### 正向腿的「到达证据」（面① 的核心纪律）
五类 gate **每一类**除断言取值外，另断言「让它走到该类的事由真发生了」：
`injected` 附判定链真被调到 + `memory_id` 指回候选；`skip_below_threshold` 附判定链真判过且 `jev_prob=0.2`
（**不带这一条，该类与「没候选」就不可区分**）；`degraded_unavailable` 附「判定链真返回 degraded」
与「无监听器兜底」**两条**到达路径；`reset` 附反向腿（块仍在时**不得**记）；
`skip_no_candidate` 附三条不同事由（候选池空 / 门控关闭 / **宿主 reject**）各自真到达。

## 六、缺陷报告（本席只报不改；写面不含 `src/**`）

### D1【缺陷 · 未修】`reset` 检测在多块场景下**漏报**
- **位置**：`packages/attention/src/index.ts:325-338`（`if (injectedBlocks.size > 0 && …) { … if (!stillThere) … }`）
- **现象**：连续注入两块（`blk-1`、`blk-2`）后，只把**最老的 `blk-1` 丢掉**（上下文里还有 `blk-2`）⇒ **不记 `reset`**。
- **实测读数**（`node --test packages/attention/tests/defect-report.test.mjs` 的 D1）：
  `t1 gates=["injected"]` → `t2 ["injected","injected"]` → `t3 ["injected","injected","injected"]`；`blk-1` 已离开上下文，`reset` 记了 **0** 行。
- **机制**：检测把**块级集合** `injectedBlocks` 当**单个布尔**用 —— `stillThere` 问的是
  「上下文里**还有没有** `<mana-memory>` 块」，于是「**仍有别的块在**」会**遮蔽**「**这一块没了**」。
- **为什么这是缺陷而不是设计**：`src/index.ts:317-319` 的自述原文把它要防的形态写得很清楚 ——
  「块『悄悄消失』与『从未注入』表面完全同形。若不检测，`inject_log` 里那行 `injected` 会**永久标着已注入**，
  而上下文里其实早没了 —— 『注入审计』就成了假账（本仓首位缺陷类：让失败不可观测）」。
  本席实测的正是**那个形态在"多块"时**发生；该自述没有排除多块。
- **后果**：每次注入 `injectedBlocks` 只增不减（`clear()` 仅在**全空**时发生）⇒ 只要上下文里**始终有任意一块**
  存活（宿主模式下同一块会一直被带上），被压缩掉的旧块的 `injected` 行就**永久是假账**。
- **修法方向（供派单参考，本席不实施）**：把「有没有块」的布尔改成**逐块核对**
  （块身份不能靠内容反查——A1-9 要求审计不泄内容；可用**每块的文本指纹**或让宿主回传的 messages
  与 `blk-N` 建立可核对的映射），或至少把 `stillThere` 收窄为「**最近一次注入的那一块**是否还在」。
  ⚠ 收窄版会把上一条假账换成下一条（旧块永远无人管）⇒ 建议按逐块方案做，并配一条
  「只丢最老那块 ⇒ 必记 reset」的新判据（本席 D1 即为它的现成形态）。
- `[建议决策] reset 检测多块漏报怎么修 | 选项：A 逐块核对（需给块一个可回读身份）/ B 收窄为"最近一块还在吗" | 推荐：A 理由：B 只是把假账挪到下一块的 `injected` 行上。`

### D2【缺陷 · 未修】`inject_log.reset` 布尔列**零生产者**
- **位置**：`packages/attention/src/index.ts:261`（`finish()` 的签名只有 `memoryId` / `blockId`，
  **不传 `reset`**）↔ `packages/core/src/index.ts:149-150` 的列语义
  「该块是否已离开上下文（**与 `gate='reset'` 配对的显式位**）」。
- **实测**：`gate='reset'` 的行 `reset` 列实测为 **0**；`src` 里 `reset:\s*true` 出现 **0** 次。
- **后果**：同一事实的两处读数**互相矛盾**，且其中一处**恒为空** —— 任何按 `reset=1` 的查询**静默归零**
  （「有列无值」正是本仓首位缺陷类）。注意 `core` 的 `degraded` 列有防呆（`|| gate===…`），
  **`reset` 列没有** ⇒ 这条缺口不会被兜底。
- **修法方向**：`finish('reset', …)` 时传 `reset: true`（一行），或让 core 在 `gate='reset'` 时自动置位
  （与 `degraded` 同款防呆）。后者更稳：**调用方忘了就不会再发生**。

### D3【已知缺口 · 自述 · 未修】`injected` 行的 `request_id` 丢掉候选 id
- **位置**：`src/index.ts:264`（`requestId: pending[0]?.requestId ?? `pre-step:${turn}``）与
  `:473-475`（`pending` 在 `finish` **之前**被清空）。
- **实测**：`request_id = 'pre-step:7'`（候选 id 是 `req-link`），而 `memory_id = 'req-link'`。
- **性质**：这条**实现自己已在注释里写明**（`:466-469` 原文：「`injected` 行的 `request_id` 实际落成
  `pre-step:N`（**丢掉了候选 id**）」）⇒ 不算新发现，本席只是把它**钉成读数**，防止它日后被当成"已修"。
- **风险**：`request_id` 是 core 定义的**关联键**（`JevJudgeRequest.requestId` 同源）。
  关联键在 `injected` 这一类行上指向**轮次**而非**候选** ⇒ 跨表回填（jev_log ↔ inject_log）在该类上不可用。
