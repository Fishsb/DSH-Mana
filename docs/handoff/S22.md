## 3. 反证判据 / 负向对拍（**任务书指定的扰动前提是假的，已换成有牙的**）

### 3.1 ⚠ 关键纠正：任务书给的负向对拍**打不到靶**

任务书⑤要求：「注释掉 `ctx.effect` 的 dispose ⇒ 卸载后路由仍在 ⇒ 必须有一条判据报红」。

**实测结论：该前提不成立。** 本席 2026-09-25 用 `node --input-type=module` 直跑五站点归属矩阵（`/tmp` 临时脚本，未动仓内任何文件）：

| 注册站点 | 卸载插件后 `'mana'` 路由 |
|---|---|
| `ctx.llm` 裸调（apply 内） | **消失** |
| `ctx.llm` + `ctx.effect` 显式 handle | 消失 |
| `ctx.effect` 但 **finisher 被挖空** | **仍然消失** ← ≠ 任务书假设 |
| **`ctx.root.llm`（注册逃出本 fiber）** | **残留 ⇒ 真泄漏** |
| `ctx.root.llm` + `ctx.effect` 显式 handle | 消失 |

**机理**：`LlmRuntime.registerAdapter` 内部就是 `this.ctx.effect(function*(){…}, 'llm.registerAdapter()')`（`node_modules/@deepseek-ai/dsh-llm/lib/types/index.js:284`）——它把 effect 挂在**调用方 fiber** 上。卸载那个 fiber 时 cordis 把它的**全部** effect 一起释放 ⇒ 宿主自己就替我们释放了路由。故「挖空 finisher ⇒ 路由仍在」是一条**永远为假**的断言。

⇒ **本席把对拍改打在归属维度上**（tests 用例⑤「差分对拍」）：同一条探针分别喂 [真实现] 与 [故意 `ctx.root` 逃逸的泄漏变体]，必须**一个「消失」、一个「残留」** —— 只跑其中一种都证明不了判据有牙。

### 3.3 ⚠ 扰动 B 未报红 —— 这是**判据集的已知盲区**，如实记

单跑 B（逃逸但 finisher 正常）**没有判据报红**。原因已实测定位：适配器的 finisher 调的是 `h()`，而宿主释放后的 `h()` 是**幂等**的：它把 `released` 置真、把 `owned` 里的路由删掉，而 `owned` 此时**已被 `registerAdapter` 自己的 fiber 释放清空** ⇒ 删了个空集，`released` 只影响后续 `replace()`。
**路由真正消失靠的是「宿主 effect 挂在本 fiber 上」这条链，不是我的 finisher。**
⇒ B 这种「逃逸但 finisher 仍在」的形态，**当前 9 条判据抓不到**。
**未覆盖面如实声明**：要抓它需读 `registerAdapter` 返回句柄的内部私有状态（`released` 不可达），或改成「注册前先记 `ctx.root` 归属」的静态分析 —— 本批**不做**，不假装已覆盖。（判据③在 **C** 形态下确实报红，故「路由残留」这条腿**不是**假绿。）
