### 3.3 收口 3：librarySize 口径修正

**改动**：`recallLexical` 的计数 SQL 由 `SELECT COUNT(*) FROM memory_items` 改为 `... WHERE retired = 0`。

**语义**：该值的唯一消费者是 `reason` 判定（`librarySize === 0 ? 'empty_library' : 'ok'`），它回答的是「**对这次检索而言**库里有没有可查的东西」；而检索 SQL 本身已排除 `retired = 0` ⇒ 全量计数与该语义**不自洽**。
**实害（复现）**：库中唯一一条记忆 `retired=1` 时，旧口径读到 `hits=[] reason=ok librarySize=1`，而 **A1-10 的判红形态正是（库非空 && 0 命中 && reason=ok）** ⇒ **正确行为被读成缺陷（假红）**。
**为何是口径修正而非行为变更**：库里**无** `retired` 行时两者数值相等 ⇒ 既有判据结论不变。

**新增机检** `packages/core/tests/library-size-live.test.mjs`（4 例，全绿）：
