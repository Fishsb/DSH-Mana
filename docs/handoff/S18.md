## 3. 反证判据（负向对拍：造扰动 ⇒ **原判据**必须报红 ⇒ 恢复 + sha256 相同）

⚠ **口径说明**（本席实测踩到的失败形态，写下来免得后人重踩）：
负向对拍必须是「**在变异体上跑原判据，断言它报红**」，**不是**"在变异体上再断言一次正确行为"
—— 后者等价于要求变异体也合格，于是它**永远红**，而与"原判据有没有牙"无关。
夹具为此提供 `expectRed(fn, why)`（`_harness.mjs`）。
**变异一律在仓外克隆副本上做**（`cloneAndMutate`：源码读进内存 → 写临时目录 → 相对 import 改写为
绝对 file: URL → import 克隆），**绝不写回仓内任何源文件**。

## 4. 回归自检

### 4.1 核心判断：本包是**消费者**还是**自有写入路径**？（任务书要求回答）

**结论：读写面在本包，写库语义在 core；本包是 core 写入口的消费者，不另建写入路径。**

依据（逐条可核）：

| # | 事实 | 位置 |
|---|---|---|
| ① | `user_model` / `user_model_history` 两表都建在 core | `packages/core/src/schema.ts:89` / `:107` |
| ② | 唯一写入口是 core 的 `updateUserModel`，主表 UPDATE 与历史 INSERT **同事务** | `packages/core/src/index.ts:447`（事务 `:453`/`:493`/`:496`） |
| ③ | 本包 `updatePreference` 是它的**受守卫包装**，不另建写入路径 | `packages/user-model/src/index.ts` 的 `updatePreference` |

**为什么不做自有写入路径**：若本包自己写这两张表 ⇒ 出现**第二个写入者**，core 那条与核心
写入口并列的路径要么变死代码、要么两个写入者语义漂移（一个有事务、一个没有）。
那正是任务书点名的「拆东墙」——为了让本包"有行为"而把 core 的既有写入点弄成死代码。
⇒ **core 的 `:471` 仍是活代码**（其写入口被本包真调用，见 A4-4② 判据）。

**那本包的"行为"体现在哪**（否则就等于"还是空壳"，白改）：
core **做不到**的三件事 —— ① 精度判定核（三个纯函数）；② A4-3 的运行期内容中立守卫；
③ 漂移报告的落 trace。其中 ③ 使**卸载可观测**：

```
判据「行为③ 卸载即净」实测：
  装载时 reportDrift ⇒ mana_trace 新增 1 行（user-model/drift）
  卸载后服务不可读 ⇒ 同一触发不再产生新行（Δ = 0）
```

⇒ 这**直接反驳**了 `docs/mana-rollout-plan.md:728` 的两句原话：「去掉用户模型…**不可做**…
卸载无差异：`user-model` 的 `apply` 只 `provide` 服务 + 注册 pass-through（`packages/user-model/src/index.ts:83-89`），
**不写任何行**」。**该行结论在 B5.2 后已过期**（原因正是本包现在写行），但
⚠ 本席**不擅改** `docs/mana-rollout-plan.md`（非本席写面）⇒ 登记为未决项 §5-1。

### 4.4 A4-2 首测方法（**未设任何目标数字** —— 册:598 明令）

产出**方法**而非阈值：`assessAccuracy(samples, threshold)` 的判定序
① 阈值未定 ⇒ `undeterminable` ② 无样本 ⇒ `undeterminable`（`hitRate=null`，不用 0 冒充）
③ `n < 289` ⇒ `undeterminable` ④ 才判 pass/fail。样本量下限由
`requiredSampleSize()` **现算**（`1.96²×0.75×0.25/0.05²` ⇒ 289），并有判据钉住
「算出来必须恰好是 289」+「改 p/半宽 ⇒ 结果必须变」（证明它是派生量而非手抄的 289）。
⇒ 若册:598 的 289 哪天与公式脱节，判据**报红**。
