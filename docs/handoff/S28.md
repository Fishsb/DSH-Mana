## 4. **核心判断**：本仓该不该有「画像写入」——三种可能，按证据选一条

**结论 = (a) + (b) 的组合；(c) 越界，只作 [建议决策]。**

| 选项 | 判定 | 依据（逐条可核） |
|---|---|---|
| **(a) 只提供「读 + 校验」面** | ✅ **采纳其中一半** | 守藏侧 `~/.dsh/suite/knowledge/{AGENT,USER}.md` 是**别系统的写面**（无 git、有独立写门 `memory-append.mjs`）。本批数据册明文：⛔ 不动守藏既有件，本仓只读。本包源码里**零 fs 写调用**（§5 有 grep 证据）；对画像载体的知识（3000 字符容量、环境覆盖变量名、归档禁碰画像节）以**只读常量**形式引用，不复制守藏的写入实现。 |
| **(b) 统一写入口 + 版本化，落本仓自己的表** | ✅ **采纳** | ① `user_model` / `user_model_history` **already exist**（`packages/core/src/schema.ts:89/107`），写入口 `updateUserModel` 已把「主表 UPDATE + 历史 INSERT」绑在**同一事务**（`packages/core/src/index.ts:451-507`）⇒ **复用即「并入既有事实源」**。② **不新建**与 `user_model_history` 语义重叠的表：另开一张就是同一条事实的两个归属地，改一处漏一处即漂移。③ 键空间用 `profile:<doc>:<key>` 把画像变更与 core 的其他用途在同一张表里分开。 |
| **(c) 本仓直接写守藏档案** | ⛔ **越界，本席一行未写** | 见 §6 的 [建议决策] S-1。 |

**为什么不是「默认选 (b) 而不给理由」**：(b) 的成立**完全依赖 (a) 已成立** —— 只有当「守藏档案不可写」这条边界为真时，「写本仓自己的表 + 由守藏另行消费」才是唯一不越界的落点。若这条边界将来松动（见 S-1），(b) 的形态也要重判。

**边界外的另一件事**：v10 §12.4「内在奖励 > 0.5 时把 Write Gate 阈值降到 0.4」—— **本批明确不做**。本内核的 `floor` 由调用方**逐次显式传入**，不接受"按信号改阈值"的入参（动态阈值会让判据阈值随信号浮动，与 `docs/contract/threshold-discipline.md` 的 A 档「跨运行可逐字复现」直接冲突）。
