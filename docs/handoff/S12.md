**实现选择与理由**：「把当前 src **重新编译**一遍，与 lib 产物**逐字节**比对」（`tsc -p <pkg>/tsconfig.json --outDir <mkdtemp> --declarationDirectory <mkdtemp>/types`）。

1. **可判定**：它比的是「产物是否**由当前 src 编出来**」这个事实本身，不依赖任何历史指纹/基线文件；
2. **不被 tsc 无关波动误伤**：比较对象恒定是「同一份 src 现编出来的产物」，注释/空白/时间戳只在**真的不同步**时才让两者不等；本机实测 12 个 tsc 包 **42 个 .js 逐个 sha256 相同**；
3. **为什么不选「导出符号集合比对」当主判据**：导出面对**方法级**改动无感 —— 本仓的实证恰是 `writeInjectLog`（`packages/core/src/index.ts:271`，`ManaCoreService` 的**方法**）与 gate 分支，它们不改变任何模块导出名。该路只留作辅助信息；
4. **ui 的特殊性**：`lib/client.js` 由真 builder 脚本产出（`packages/ui/scripts/build-client.mjs`，单产物契约 A5-5），故**重放真脚本本体**（拷到临时目录跑），不在判据器里二次实现那个文本变换（否则是**两个真源**）。
5. **零写入**：所有重编译/重放都写进 `mkdtemp`，仓内 lib 一个字节都不动（有实测断言，见 §三）。
6. **档位语义未变**：ARTIFACTS 仍是挂账态，仍可被 `--require-fresh-artifacts` 升级为 FAIL。

- 探针模式：`tools/a1-check.mjs:200-330`（`--embed-reach-probe`，输出**单行 JSON**）

**为什么用子进程做两态**：undici 的 `EnvHttpProxyAgent` 在进程启动时读环境变量，同进程内改 `process.env` 不会换掉已建好的 dispatcher ⇒ 两态只能靠**重新起进程**。

**报错文本点名延迟来源 + 实测耗时**（要求①），归因分 7 类而非「一句 Ollama 不可达」：

| 类别 | 判据 |
|---|---|
| `OK` | 真通（带 dim、嵌入 ms、TCP ms）|
| `REFUSED` | cause 链含 `ECONNREFUSED` ⇒ 端口无监听，**是服务没在跑** |
| `TIMEOUT_AFTER_CONNECT` | **TCP 已连上**却没在 timeoutMs 内答完 ⇒ 服务在、就是慢 |
| `TIMEOUT_BEFORE_CONNECT` | TCP 没连上且无明确拒绝 ⇒ **「慢」与「不可达」不可分辨**（如实标注，不替读者下结论）|

| `DNS` / `CONFIG` | 解析失败 / 配置面失败 |

### 2.4 批次 3 · 单实例锁（拍板口径 A）

- 模块：`tools/checker-lock.mjs`（141 行，两个 checker 共用）
- a0 接入：`tools/a0-check.mjs:107-176`；a1 接入：`tools/a1-check.mjs:341-402`
- 退出码：拿不到锁 **a0 = 3**（`tools/a0-check.mjs:135`）、**a1 = 4**（`tools/a1-check.mjs:398`）—— a1 的 3 已被「变异自证腿不过」占用，故用 4，两者都写进了文件头注释。

```
$ node tools/a0-check.mjs   # 并发被拒时
✗ 另一个 a1-check 实例正在运行 —— 本实例拒绝启动（**不排队**）
  持有者：pid=412093 起始时刻=2026-09-25T03:21:16.272Z commit=7a44dd7 模式=judge 参数=(无参数)
  锁文件：/tmp/mana-check-1d25dc95a9-a1-check.lock
```

**关键设计（都是被实测逼出来的）**：
1. **判定锚点是 `kill(pid,0)` + `/proc/<pid>/stat` 的 starttime，不是 mtime/时间戳** —— 后者是代理指标；
2. **PID 复用防护**：只靠 `kill(pid,0)` 时，崩溃残留的锁若碰上被复用成同号的无关进程会**永久卡死**。实测验证：`startToken` 不符即判陈旧并接管；
3. **原子创建**：`openSync(path,'wx')`（O_EXCL），不用「先 existsSync 再 write」的两段式（TOCTOU）；
4. **接管留痕**：`[lock takeover] {陈旧持有者 + takenOverAt + takenOverBy}` 打到 stderr；
5. **锁文件放 `$TMPDIR` 而非仓内**：仓内锁是运行态，会给 git 写席制造未跟踪噪声（且本席写面不含 `.gitignore`，不能去加忽略）。按**仓库根路径哈希**取键 ⇒ 不同 checkout（如 /tmp 副本）各自独立持锁，不产生假红；
6. **a0 同时持有 a0-lock 与 a1-lock**（`tools/a0-check.mjs:127-140`）：因为 a0 的 A1 腿会 **spawn 一个 a1-check**（`tools/a0-check.mjs:944`）。只锁自己时，a0 与并发的 a1 会让 **A1 腿报红**，读者会把「有人并发跑 a1」误读成「A1 判据挂了」——本席**实拍到了这个形态**（见 §三 对拍 D 首轮）。现在 a0 把 `--held-lock <uuid token>` 传给子 a1，子 a1 只**校验**（锁存在 + pid 是父进程 + token 逐字相等）不重复获取；校验不过一律 exit 4。
7. **`--record-baseline` 与普通判据互斥**：锁 meta 里有 `mode: 'record-baseline' | 'judge'`（要求③）。

## 五、未决项

1. **【需拍板】内容腿的代价**：每次 ARTIFACTS 判据要多花 **~10s**（13 包重编译 + ui 脚本重放实测 9903–12046ms）。当前它跑在每个 `a0-check` 里（A1 入口腿 ⇒ a0 会连带跑），即**每次 a0 全量 +10s**。可选：(A) 保持现状；(B) 仅当 mtime 腿报「可疑」或带 `--require-fresh-artifacts` 时才做内容重编译（快，但**mtime 腿报「新鲜」的假绿场景就不会被触发**——正是要防的那一类，故本席不推荐）；(C) 加 `--content-artifacts` 开关，缺省关闭（则**默认运行看不见假绿**）。
2. **【建议决策】A1-12 真机腿的 timeout 语义** | 选项：A 保持 30000（现状，与 `embed.ts` 本地缺省一致）/ B 由一个**显式环境变量**控制并被报告记录 | **推荐 A**，理由：改它就是「改测量条件」，而测量条件一旦浮动，「这条红是判据问题还是环境问题」又会变成不可归因。本席本轮**实测到**该腿会从 23ms 飙到 **6581ms / 7055ms**（发生在 `npm test` 负载期间；安静态 12 次采样为 17–47ms，两态之间无系统差异）—— 距 30s 阈值仍有约 4 倍余量，故暂不需要动，但**余量正在被观测到在缩水**，值得进无人值守前重新评估。
3. **未验证**：`TIMEOUT_AFTER_CONNECT` 类别（「已连接但没有按期答完」）在**本机真环境**里没有造出过 —— 本机 Ollama 稳定在 17–47ms，而造这个条件需要「一个接受连接但不回包的端点」，本席未为此引入新夹具（那不属写面，且会引入新依赖）。该分支的**判据逻辑**只经代码走查（`conn.ok === true` 且 cause 含超时类 ⇒ 归 `TIMEOUT_AFTER_CONNECT`），**未实测**。
4. **未验证**：`DNS` 类别的归因是**间接**的 —— 本机实测 `no-such-host-xyz.invalid` 走的是「非本机端点缺 apiKey」⇒ 先被判成 `CONFIG`。要真验 DNS 需一个「本机地址 + 解析不了」的组合，本席未构造。
5. **`a0` 的两项 FAIL 不是本席能闭合的**：A0-10（别席提交越界）需**唯一基线席**在干净树上重取基线；A0-12（清单腿少 3 件）同理。本席按并发纪律 §2 **未执行** `--record-baseline`。
6. **`tools/checker-lock.mjs` 是新增文件**，需要主持人 `git add` 时**一并纳入**（否则两个 checker 都会 import 失败 ⇒ 直接 exit≠0）。这是本席交付里唯一需要「提交时别忘了」的项。
